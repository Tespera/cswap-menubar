# cswap · 多语言方案（中文 + 英文）

状态：**方案已定，下个版本实施**（用户 2026-11-11）。本文是开工依据；实施时发现与本文冲突的情况，先改本文再改代码。

## 1. 目标与范围

- 界面全部支持**简体中文**和**英文**，以后可能加第三种语言，但不为它提前做设计。
- 默认**跟随系统语言**：系统首选语言是中文（任何中文变体）时显示中文，其他一律显示英文。
- 范围：面板所有页面、菜单栏悬停说明、右键菜单、对话框、系统通知、首次引导、错误提示、Info.plist 里的介绍文案、README 展示图。
- 不在范围：
  - `CHANGELOG.md` 和 App 内的更新日志页：保持中文（见 §7 待定 2）
  - `docs/` 下的开发文档
  - 代码注释
  - cswap 命令行自己输出的英文原文：作为错误详情原样显示，不翻译

## 2. 技术方案：代码里的双语文案表（方案 A）

| 方案 | 结论 | 原因 |
|---|---|---|
| **A. 代码里的双语文案表** | **采用** | 漏翻译直接编译不过；测试能指定语言；带数字、单复数的句子用函数写，最自然；不依赖 Xcode |
| B. 老式 `.strings` / `.stringsdict` 文件 | 否 | 漏翻译要到运行时才发现；单复数要另写一种文件；资源要从 `.copy` 改成 `.process`，打包脚本也要跟着改。以后真要加第三种语言、交给翻译平台时再迁过去 |
| C. String Catalog（`.xcstrings`，苹果现推荐） | 否 | 本机只有 Command Line Tools，没有 `xcstringstool`，编译不了（2026-11-11 已实测） |

### 2.1 结构

- `CswapCore` 里新建一个文案模块（暂定 `Strings.swift`，量大时按页面拆成几个文件），**全部**界面文字只在这里定义：
  - 固定文字：每条同时写中文和英文，例如 `static func addAccount(_ l: Lang) -> String { l == .zh ? "添加" : "Add" }`，或者用一个只有 `zh` / `en` 两个字段的小结构体。具体写法开工时定，要求是**少写一种语言就编译不过**。
  - 带变量的句子写成函数（`refresh(in:)`、`switchedTo(name:)`），语序、单复数在函数里各自处理，不拼接半句话。
- `Lang` 是一个只有 `.zh` / `.en` 的枚举：启动时从系统首选语言算出来，作为一个值传进 `OverviewBuilder` 等纯函数（和现在传 `now` 一样），**不在纯函数里读全局状态**。这样测试能分别跑中英两套。
- 视图层、通知、对话框也只从文案模块取文字，代码里不再出现中文字面量。加一条测试兜底：扫描 `Sources/`，字符串字面量里出现汉字就失败（注释不算）。
- 时间格式统一走 `Fmt`，按 `Lang` 输出（见 §4）。日历仍用本机系统时区（`/etc/localtime`），这条不变。

### 2.2 语言怎么定

- 读系统首选语言列表，第一个以 `zh` 开头 → 中文，否则英文。
- 打包时 Info.plist 写 `CFBundleLocalizations = [zh-Hans, en]`、`CFBundleDevelopmentRegion = en`，这样「系统设置 → 通用 → 语言与地区 → App」里就能单独给 cswap 指定语言，App 也会跟着变。
- App 设置里**不放**语言选项（见 §7 待定 1）。
- 切换语言后重启 App 生效即可，不做运行中热切换。

## 3. 英文文案原则（用户 2026-11-11 定）

**本地化，不是直译**：按英文用户的习惯表达同样的意思，不保留中文的句式。英文能用通行简写的就用简写，减轻 320pt 面板的排版压力。

1. **只用大众认得的简写**：`5h`、`2h 14m`、`45s`、`Tue`、`Nov 21`、`min`、`%`。不发明简写：可以写 `5h`，不写 `5hr lim.`。
2. **说结果，不说实现**：和中文同一条原则（见 auto-memory「界面文案站在用户视角」）。
3. **macOS 习惯**：
   - 按钮、菜单项、开关标签用 **Title Case**（`Switch`、`Open in Terminal`、`Launch at Login`）。
   - 说明文字、提示、通知正文用**句子大小写**（`Switches when usage hits 90%`）。
   - 会弹出对话框或子页的菜单项结尾加 `…`（`Remove Account…`）。
4. **短**：能用一个词就不用一句话，能省主语就省（`Resets in 2h`，不写 `This account resets in 2 hours`）。
5. **数字与单位**：简写时数字和单位之间不加空格（`2h 14m`、`5min`）；百分号紧贴数字（`90%`）。
6. **单复数**：拼写完整的地方要处理单复数（`1 account` / `2 accounts`），简写的地方不需要。
7. **同一个东西只有一个叫法**：以 §5 术语表为准，界面里不出现近义词混用。

## 4. 时间与数字格式

| 场景 | 中文 | 英文 |
|---|---|---|
| 一天内刷新 | 2 时 14 分后刷新 | Resets in 2h 14m |
| 超过一天刷新 | 周三 14:57 刷新 | Resets Wed 14:57 |
| 正在刷新 | 正在刷新 | Resetting… |
| 不到 1 分钟 | 不到 1 分 | <1m |
| 预计用完（一天内） | 预计 5 时 20 分后用完 | Runs out in 5h 20m |
| 预计用完（超过一天） | 预计周二 09:55 用完 | Runs out Tue 09:55 |
| 登录有效期 | 11 月 21 日 | Nov 21 |
| 更新时间 | 3 分钟前更新 / 刚刚更新 | Updated 3m ago / Updated just now |
| 重试 | 4 分钟后重试 | Retrying in 4m |
| 切换记录时间 | 今天 06:12 / 昨天 22:40 / 11-05 11:08 | Today 06:12 / Yesterday 22:40 / Nov 5 11:08 |

- 两种语言都用 **24 小时制**（已定决策，不改成 AM/PM）。
- 星期、月份英文用固定的三字母简写表，不交给系统按地区格式化（系统会因地区设置不同而输出不一样的结果，界面宽度就没法控）。

## 6. 排版

- 面板宽度 320pt **不变**，英文按 §3 简写后应能放下；放不下就先改文案，再考虑改布局，最后才考虑缩小字号。
- 重点检查：
  - 账号行两列用量（列宽 92pt）
  - 设置页分段按钮（`30s / 1m / 5m`、`5h / Weekly / Both`）
  - 自动切换页策略说明
  - 底部状态行
  - 头部状态点（`Near limit` 比「快到切换阈值」短）
  - 对话框
- Snapshot 改成中英各出一套（文件名加 `-zh` / `-en`），逐页对比。
- 截图自查之后再上真机看一遍：`cswap-app --show …` 配合系统设置里把 App 语言临时切到英文。

## 7. 待定（开工前请用户确认，当前按推荐写）

1. **App 里放不放语言选项**：推荐**不放**。跟随系统就够了，想单独改的人可以去系统设置里给 App 指定语言。
2. **更新日志要不要出英文版**：推荐**保持中文**。界面双语，CHANGELOG 和 Release 说明暂不翻译；不然每次发版要写两份。等有英文用户反馈再说。

## 8. 实施步骤与验收

1. 建文案模块和 `Lang`，`Fmt` 按语言输出；`OverviewBuilder` 等纯函数加语言参数。
2. 逐个文件把中文字面量迁进文案模块，同时写英文（约 340 处，分布在 20 个文件，2026-11-11 统计）。
3. 测试：现有中文断言保留；关键映射（用量卡、账号行、状态点、自动切换说明、通知文案）加一套英文断言；加「Sources 里没有汉字字面量」的扫描测试。
4. Info.plist 声明两种语言；介绍文案出英文版。
5. Snapshot 中英双套，逐页修排版；`tools/readme-art` 的英文图换成英文界面。
6. 真机检查一遍英文界面，确认系统设置里能单独切换 App 语言。
7. 版本号升第二位，CHANGELOG 记一笔。

**验收**：系统语言为英文时，所有页面、菜单、对话框、通知里没有一个汉字（用户自己起的中文别名除外），没有文字截断或换行错位；切回中文，与现在的界面完全一致。
