# cswap · 技术方案

## 1. 总体边界

- **App 只调命令、读结果**：账号、令牌、凭据、用量抓取、自动切换决策全部由命令行 cswap 完成。App 不读写 cswap 的凭据文件、钥匙串和 `sequence.json`。
- 例外（只读）：cswap 日志 `~/.claude-swap-backup/claude-swap.log`（切换记录）、更新缓存 `~/.claude-swap-backup/cache/update_check.json`（最新版本号）。这两处都不是稳定接口，解析失败要降级（隐藏对应信息），不能崩。
- 命令行不提供的能力由 App 自建，清单见 `02-功能清单.md` 的「App」来源项。

## 2. 技术栈

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 / 构建 | Swift 6.4 + SwiftPM，**只装 Command Line Tools，不依赖 Xcode** | 本机现状；与 NetHub 一致 |
| 界面 | AppKit `NSStatusItem` + 自定义 `NSPanel` 承载 SwiftUI 视图 | 菜单栏要显示**彩色百分比**（橙 / 红），`MenuBarExtra` 的标签只能稳定显示单色（NetHub 已踩过） |
| 最低系统 | macOS 14 | 自用，本机 macOS 27；留余地 |
| 测试 | Swift Testing（`@Test`），按 NetHub 的 `Package.swift` 显式加载 TestingMacros 插件 | CLT 里没有 XCTest |
| 登录时打开 | 用户级 LaunchAgent（仿 NetHub `LaunchAgentManager`） | 无付费证书时 SMAppService 不可靠（NetHub 实测） |
| 通知 | 先试 `UNUserNotificationCenter`；签名 / 权限不成再退回 `osascript display notification` | 自签名包能否正常弹 UN 通知**未验证**，P5 阶段实测 |

### 只装 CLT 的硬约束（照搬 NetHub CLAUDE.md 的结论）
- 不用 `@State`（macOS 27 SDK 起是宏，插件只随 Xcode 发）。用 `@StateObject` + 小 `ObservableObject`（见 NetHub `HoverState`）。
- 测试目标保留 `-load-plugin-library <TestingMacros>` 的 unsafeFlags。
- 字体用 NSFont 构造的 `F.sys / F.num`，颜色用 `T.*`。

## 4. 调用命令行（CLI.swift）

- **定位**：`~/.local/bin/cswap` → 登录 shell（`/bin/zsh -lc 'command -v cswap'`）→ 找不到则进入「未安装」状态。
- **干净环境**：子进程环境里删掉 `CLAUDE_CONFIG_DIR`（cswap 在 `cswap run` 会话里会拒绝很多命令，`_refuse_session_shell`）；补齐 PATH（含 `~/.local/bin`）；保留代理变量（cswap 联网取用量要走代理）。
- **只读命令可并发**（`list --json`、`status --json`、`config list --json`、`priority`、`--version`）；**写命令串行**（switch、add、remove、alias、disable/enable、threshold、priority、config set/unset、upgrade），写完立即刷新一次 `list --json`。
- **超时**：只读 20s，写 30s，upgrade 5 分钟；超时杀进程并报错。
- **错误**：`--json` 命令出错时 stdout 是 `{"schemaVersion":1,"error":{...}}` + 非零退出码，解出 error 显示给用户；非 JSON 命令取 stderr 最后几行。
- **交互式确认**：`remove` 往 stdin 写 `y\n`；`add --slot N` 只在核对过当前登录邮箱后调用（避免触发覆盖确认）。其余命令 stdin 接 `/dev/null`，任何意外的 `input()` 会立刻 EOF 失败而不是挂住。
- **schemaVersion**：不是 1 时界面提示「cswap 版本不兼容」，不硬解。

## 5. 数据刷新

- 定时：按「刷新频率」（默认 60s）调 `list --json`；面板打开时立即刷一次。
- 当前账号变化（别处切了号）：每次 list 结果里 `activeAccountNumber` 变了就更新界面，并在切换记录里记一条「命令行」来源（若 App 没有对应记录）。
- 优先级：只在打开账号详情 / 自动切换设置时读 `cswap priority`。
- 设置：打开设置页时读 `config list --json`。

## 6. 自动切换（AutoSwitchService）

- 开关状态存在 App 自己的设置里（UserDefaults），**cswap 没有这个设置项**。
- 开：启动 `cswap auto --json` 子进程（不传 --threshold 等参数，全部读 cswap 的 `autoswitch.*` 设置，保证与命令行一致），逐行读事件：
  - `switch` → 刷新数据、写切换记录（来源「自动」）、发通知 F1
  - `all-exhausted` → 通知 F2
  - `account-quarantined` → 通知 F4、刷新
  - `error` → 记日志，面板底部提示
  - 未知事件忽略（上游约定事件类型只增不减）
- 子进程意外退出 → 退避重启（5s、30s、2min，之后每 5min）；连续失败在面板显示「自动切换没在运行」+ 原因。
- 设置变更（阈值、策略、冷却等）→ 重启子进程。
- App 退出 → 结束子进程（SIGTERM，3s 后 SIGKILL）。
- **与上游菜单栏互斥**：上游菜单栏服务里也能跑自动切换引擎，两边同时开会重复换号。用户已决定不再安装上游菜单栏，App 不做检测。

## 7. App 自己的数据

位置 `~/Library/Application Support/cswap/`：
- `history.json`：App 发起的切换和 auto 事件（时间、从、到、来源、原因），保留最近 200 条。
- `notify-state.json`：登录过期提醒的「今天已提醒」记录。
- 偏好（菜单栏显示、刷新频率、通知开关、自动切换开关）用 UserDefaults，域名 `com.eric.cswap`。

## 8. 打包与签名

- `tools/package.sh`：`swift build -c release`，组装 `cswap.app`（Info.plist：`LSUIElement=true`、bundle id `com.eric.cswap`、名称 cswap），拷图标资源。
- 签名：自签名证书「cswap Code Signing」（2026-11-09 建，有效 20 年）。私钥与 .p12 只在本机 `~/.config/cswap-signing/` 和仓库密钥 `CSWAP_P12_BASE64` / `CSWAP_P12_PASSWORD` 里；本地打包和 CI 用同一张。没有证书时本地退回临时签名并提示，CI（`CSWAP_REQUIRE_CERT=1`）直接失败。
- 证书是自动更新的信任根：App 只接受和自己同一 bundle id、同一张证书签名的新包。**证书丢了或换了，已装的 App 就不认新包了**（只能手动下载安装一次）。
- 安装到 `/Applications/cswap.app`；App 名与命令行同名不冲突（命令行在 `~/.local/bin/cswap`）。

## 9. App 自动更新与发布

- 发布：本地 `tools/package.sh release`（检查工作区干净、CHANGELOG 有本版本一节）打 `v<版本>` 标签并推送 → CI（`.github/workflows/release.yml`）测试、打包、签名，发 GitHub Release，附件 `cswap-<版本>.zip`，说明取 CHANGELOG 那一节。
- 检查：启动 30 秒后、之后每 6 小时下载最新 Release 里的版本清单 `latest.json`（`github.com/…/releases/latest/download/latest.json`，失败走 gh-proxy.com）。**不用 `api.github.com`**：匿名每个出口 IP 每小时 60 次、同网络的程序共用，2026-11-09 实测被用完（0.3.2 及更早的 App 仍走 API）。
- 下载：先直连 GitHub，失败走 gh-proxy.com；有 GitHub 给的 sha256 就核对；`ditto` 解压后核对 bundle id、版本号，再用当前 App 的指定要求（`identifier + certificate leaf`）核对签名。不符就丢弃并在设置页显示「更新失败」。
- 安装：自动更新打开时，等面板关着、没有正在执行的命令才装；把旧 App 挪到缓存目录、新 App 放进原位置（第二步失败就把旧的放回去），然后重启：由「登录时打开」的 LaunchAgent 拉起的，以非零码退出，让 launchd 重新拉起；否则起一个独立会话的小脚本，等本进程退出、再等 1 秒后 `open -n`，确认新进程起来了才结束（最多 5 次）。旧进程一消失就 `open` 会撞上 LaunchServices 还没登记退出，只激活不启动（2026-11-09 实测 0.3.1 → 0.3.2 没起来）。
- 提醒：菜单栏图标不变、不发系统通知。装好后第一次打开面板，底部显示「已更新到 x · 更新日志」，关掉面板后不再出现；关了自动更新时有新版本、或更新失败，设置齿轮上亮小红点。检查失败一天内不露出来。
- 开发运行（不是 .app）不检查；临时签名的 App 只提示新版本，按钮打开发布页。
- 状态到文案的映射在 `CswapCore/AppUpdate.swift`（有测试），网络与安装在 `CswapUI/Services/AppUpdater.swift`。
